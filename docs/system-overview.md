# Poise 系统说明

本文说明当前实现的架构和运行语义：按什么边界分层、一步是怎么走的、哪些安全规则在什么地方保证。策略本身的设计（批次、格子、限速、观点失效、风控阈值）见 [分批主仓与网格设计](layered-grid-design.md)，术语见 [GLOSSARY.md](../GLOSSARY.md)。具体字段和行为以代码和测试为准；验收测试按设计里的验收编号（B1、B37……）命名，可以从编号找到对应的测试。

## 分层

- `strategy/`：纯计算，不碰网络、数据库和时钟（时间由调用方传入）。
  - 参数与校验（`config`）、批次和格子划分（`batch`、`grid`、`side`）；
  - 状态与记账（`state`、`ledger`）、规划（`planning`）、判定（`decision`）、限速（`throttle`）；
  - 接管已有仓位（`takeover`）、资金预检（`funds`）、满仓压力测试（`stress`）、观点失效（`invalidation`）、预览表格（`preview`）。
- `runtime/`：唯一写入入口。
  - `Runtime` 把纯计算接到真实世界：订单先写库再发送、按成交记账、核对仓位和订单、重启恢复。
  - `store`：SQLite 存储。`api`：网页接口。`serve`：常驻服务。
  - `exchange`、`account`：交易所和账户接口；`simulated`、`simulated_account`：测试用的模拟实现。
- `hyperliquid/`：实现 `Exchange` 和 `Account`。负责签名、下单撤单、按 `cloid` 查订单、成交和仓位、账户读数（保证金、杠杆、费率、资金费）。
- `cli/`：命令行 `poise`（`check`、`serve`、`status`、`stop`、`instances`）、实例的查找（`~/.poise/<名字>`，`POISE_HOME` 可换根目录）和实例锁。`stop` 在服务运行时改走服务的本机接口，不动失效中的策略。
- `console/`：网页控制台。只发请求、只显示服务端给的数据，不重算数量和金额。接口只监听本机地址，并拒绝 `Host` 或 `Origin` 不是本机的请求（跨站的简单请求、DNS 重绑定）。

## 策略状态

| 状态 | 含义 |
| --- | --- |
| 运行中 | 按常规一步一步挂单 |
| 恢复中 | 进程重启后，等遗留订单过期、撤掉、对完账，之后转运行中 |
| 暂停中 / 已暂停 | 不下新单；暂停中还在撤单对账 |
| 停止中 / 已停止 | 撤干净、对完账之后归档，仓位保留 |
| 失效中 / 已失效 | 越过观点失效价后撤单、用只减仓单减到剩余数量；完成后归档 |

已停止和已失效都是归档：只读，不再驱动。

状态先落库再动手：落了「暂停中」就一张新单都不下，进程崩了重启后也一样。

## 一步

常驻服务按节拍驱动每个要驱动的策略（运行中、恢复中、暂停中、已暂停、停止中、失效中），各个策略并发走步：一个策略在交易所上卡住不拖延别的策略的失效价检查和撤单。同一个策略同一时刻只能走一步；网页上的暂停、停止等操作和常驻服务用同一把锁，不会并发；锁是先到先得的，操作排上队后当前这一步一走完就轮到它，常驻服务这一轮跳过，等 30 秒还没轮到才报忙。

运行中的一步（`runtime/src/runtime/step.rs`）分三段：

1. **读取**
   - 先读账户保证金率：超过停止阈值时马上按 `cloid` 撤掉非只减仓单，后面哪一项读取失败都不能让它们留在场上。
   - 设了失效价时先看一眼标记价：越过就转失效。
   - 补拉成交、核对订单（不在挂单列表里的按 `cloid` 查终态）。
   - 按主仓成交推进批次，按限速放行下一个单位。
   - 读标记价：收到时新鲜且越过失效价，就不再做后面的读取，直接转失效。
   - 读可用资金，核对仓位：交易所仓位和按状态算出的应有持仓比较，数据还在变就最多重读三轮。对不上的差额还要持续满 30 秒才算失败（成交后交易所的仓位、挂单、流水接口不是同一时刻更新），之前按「仓位数据还在变化」等待、不发新单。
2. **判定**（`strategy/src/decision.rs`，纯计算）：
   - 仓位对不上、成交流水对不上，就暂停；
   - 有结果未知的订单、行情或保证金率读不到，就不发新单，在场挂单保留；
   - 保证金率超过停止阈值，就只发、只保留只减仓单。
3. **执行**：
   - 先撤单。撤销结果不明时，这一步不发新单。
   - 再发单，只减仓单排在前面。增仓单要先过资金预检：同一账户共用一把锁、一份额度；保证金不足被拒后按 1、2、4…60 秒退避。
   - 发单前看读数有没有过期：标记价和保证金读数里更旧的那个超过行情过期时间就不再发。保证金读数是步首读的，同步和核对花掉的时间可能已经让它过期，这时再读一次，闸门状态没变就按新读数的时刻发单。
   - 有一张单结果未知，这一步剩下的都不发。
   - 被交易所以操作次数超限拒绝时暂停。

每步结束落一份视图快照。网页的列表和详情只读快照和库，不去问交易所。读取阶段没走通（成交或挂单查不到）的一步也在快照里写明原因，等待原因记为「成交待对账」，页面不会一直显示上一步的「没有等待」。

只撤单的状态（暂停中、停止中、恢复中）走同一段「撤单 + 按 `cloid` 核对终态」。查询失败也照撤：撤哪几张单只看库里的 `cloid`。哪一段没走通，这一步就不能宣告完成。

已暂停的一步只看失效价，别的什么都不做。

## 安全规则在哪里保证

- **先写库再发送**：订单在发出去之前必须已经落库（`place_one`），崩溃后能按 `cloid` 追回。
- **订单有效期**：每张单带交易所侧的 `expiresAfter`，按实际发送时刻算。超过这个时刻才送到的请求，交易所会拒绝。
- **结果未知的订单**（`runtime/src/runtime/unknown.rs`）：查不到的单记成结果未知，有结论之前本策略不发新单。只有同时满足下面三条才作废、释放预留：交易所从没确认过它、过了 `expiresAfter` 加 30 秒、没有成交且仓位核对一致。
- **记账以订单状态为准**（`runtime/src/runtime/reconcile.rs`）：累计成交量取挂单列表和按 `cloid` 查到的状态，只接受更大的值，和到达顺序无关。成交流水按交易所成交标识去重后存下，只做审计、限速计时和算盈亏（成交价、手续费），不挡记账、暂停和归档；每步从同步点往前 60 秒拉，最多往前 1 小时，只有结果未知的订单把起点钉在它的发出时刻。
- **重启**：运行中的策略先落「恢复中」，遗留订单收干净之前一张新单都不下。失效中的策略不受影响，重启后继续减仓。
- **观点失效**（`runtime/src/runtime/invalidation.rs`、`strategy/src/invalidation.rs`）：
  - 每一步先撤全部订单，再按实时仓位发立即成交否则撤销的只减仓单；
  - 补发数量扣掉还可能成交的减仓单（含结果未知的）；
  - 减仓成交不进批次、格子账本：应有持仓直接扣掉它，批次表和格子表按「先网格、后主仓」现算显示；
  - 全部订单有结论、仓位不超过剩余数量（或只剩下不了单的尾量）才转已失效；
  - 运行中、恢复中、暂停中、已暂停都会触发，停止中不触发。
- **兜底单**（`runtime/src/runtime/backstop.rs`）：设了失效价时，每一步开头按实时仓位对齐交易所上的止损触发单；它单独记在 `backstops` 表里，不进订单账本。成交过就转失效中；停止中、失效中、平仓中撤掉，撤干净才归档。
- **对外提醒**（`runtime/src/notify.rs`，飞书实现在 `cli/src/feishu.rs`）：越过失效价、已失效、已平仓、自动暂停、兜底单触发或挂不上、保证金率换档、反复撤挂（`runtime/src/runtime/churn.rs`）、驱动连续 5 分钟出问题、服务启动和退出。提醒不带仓位、数量和金额；送不出去只记日志，不挡交易。
- **账户风控**：账户保证金率、满仓压力测试、资金预检、每日操作次数（Unified 账户每天 5 万次，超过 80% 提醒）、资金费率提醒。阈值在账户风控设置里改，存在数据库里。

## 存储

一个实例一个 SQLite 文件（`data_dir/poise.sqlite`），`PRAGMA user_version` 记版本，版本对不上的旧库拒绝打开，不自动迁移。

| 内容 | 表 |
| --- | --- |
| 策略、草稿、参数版本 | `strategies`、`drafts`、`config_versions` |
| 批次、格子、限速状态 | `batch_states`、`cell_states`、`throttle_states` |
| 订单与成交 | `orders`、`fills` |
| 视图快照与暂停原因 | `strategy_views`、`pause_reasons` |
| 账户风控设置 | `account_settings` |
| 每日操作次数 | `action_counts` |
| 兜底单 | `backstops`（后加的表，已有的库打开时自动建，不改结构版本） |
| 资金费结算 | `funding_payments`、`funding_syncs` |
