# 分批主仓与网格设计

日期：2026-10-15 起草，2026-10-16 按实现修订。状态：已实现，本文与当前代码一致；架构和运行语义见[系统说明](system-overview.md)，术语见[术语表](../GLOSSARY.md)。正式网上走过新建、预览、确认启动、暂停、恢复、停止，其余只在测试网验证过（第 14 节）。

## 1. 目的与范围

在冷静时决定，在慌乱中成交：价位、批次和观点失效价由用户在想清楚的时候定好，程序在波动中按它们执行。

**用户表达的是仓位观点**：
- 看多或看空时，分批积累主仓，留着等趋势；其余仓位做网格 T，降低整体成本。
- 没有方向时，做中性网格；多空两侧的厚薄可以不同，用来表达偏多或偏空的程度。

**实现方式**：用分批挂单和网格表达这些观点。其中交易所本身做不到、必须由程序完成的是两件事：
1. **在 Hyperliquid 上自动运行网格**。HL 官方订单类型有 Scale（区间内多张限价单）和 TWAP，但没有网格；“买成挂卖、卖成挂回买”需要程序完成。来源：[Hyperliquid 订单类型](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/order-types)。
2. **可选的限速**：单边快速行情中不一次加满。HL 的 TWAP 子单是市价单，最大滑点 3%，到达最高价时整单终止，不能做到“只在认可价位、按时间慢慢建仓”。

**本期范围**：只做 Hyperliquid 永续，用户使用的 Unified 账户，单向持仓；支持做多、做空、中性三种网格。品种是主市场上的主流加密货币，加上第三方市场（HIP-3）`xyz` 上的黄金、原油、美股，标的写成 `xyz:GOLD`、`xyz:CL`、`xyz:TSLA`。第三方市场只支持明确用 USDC 抵押的；标的必须是全仓（正式网 `xyz` 的这些标的都支持全仓）。

**后续事项**：
- 第三方市场部署者在策略运行中改了费率时自动重新校验（现在运行中的策略沿用启动时的费率）；
- 美股、原油休市时段的处理（没有实测过）；
- Binance、Bybit、OKX 适配；
- 自动远期退出；
- 自定义每批数量或每格数量。

**设计原则**：
- 用户在 poise 里完成全部操作：建仓、调整、停止、平仓都有入口，不需要再去交易所页面补步骤。
- 只守三条底线：不卖主仓、不超过最大仓位、异常时暂停并与交易所对账；风控按仓位和保证金设计，不按亏损金额设计（第 7 节）。
- 其余情况能简单处理就简单处理，不为罕见的异步交错设计专门规则。

## 2. 用户配置

### 2.0 配置放在哪里

所有策略和账户级风控都存在数据库里，用户在网页控制台上新建、预览和管理，不编辑配置文件。网页之外只保留程序启动前必须知道的少量内容：

| 内容 | 位置 |
| --- | --- |
| 策略参数、账户级风控阈值、行情过期时间 | 数据库，网页管理；策略参数每次保存记录一个版本，账户级设置只保留当前值 |
| 测试网或正式网、账户地址、交易所私钥（Hyperliquid API 钱包）、数据目录、监听地址 | 实例目录里的启动文件，由用户自己编写；实例目录在仓库之外，不提交。连哪个网络由启动文件决定，正式网要用户自己写入正式网私钥 |

控制台只监听本机地址，因为在网页上可以直接启动真实交易。数据库第一次用时记下网络和账户，之后换网络或账户就拒绝启动：测试网和正式网用各自的数据目录，测试网的策略不会被拿到正式网上恢复运行。

**私钥规则**：
- 系统**从不生成、写入或修改私钥**，只在启动时从启动文件读取。私钥不经过网页表单，不进数据库、日志、界面和接口响应。
- 启动文件只允许当前用户读写（权限 600），否则拒绝启动并提示修改权限。
- **启动校验**：读不到私钥，或由私钥推出的 API 钱包地址不是该账户已授权的 API 钱包时，拒绝启动，并说明是哪一项、哪一步失败。不能用“已读取”代替“可用”。
- 以后可以改为从 macOS 钥匙串或密码管理器读取；这属于后续事项。
- 界面只显示由私钥推出的 API 钱包地址，供用户核对，不显示私钥本身。

### 2.1 两侧

一个策略最多有两侧：
- **多头侧**：在下方，价格下跌时建多仓；
- **空头侧**：在上方，价格上涨时建空仓。

| 网格 | 配置的侧 | 主仓 |
| --- | --- | --- |
| 做多 | 只有多头侧 | 可设，比例 `r` |
| 做空 | 只有空头侧 | 可设，比例 `r` |
| 中性 | 两侧都有 | 没有，`r` 固定为 0 |

**为什么中性网格没有主仓**：主仓表达的是方向观点，中性网格表达的是没有方向。HL 是单向持仓，两侧都留主仓时，一侧的开仓在交易所层面就是在平掉另一侧的主仓。想要“做 T 同时在一边留底仓”，应该用做多或做空网格加主仓来表达。

**两侧之间要留出空隙**：多头侧的最高价必须低于空头侧的最低价。两侧的空隙位置、价格范围、最大仓位都由用户自己定，不要求在网格中间，也不要求等于当前价。

### 2.2 每侧的配置

以多头侧为例，空头侧方向相反（第 5 节）：

| 配置 | 含义 | 例（价格以千美元计） |
| --- | --- | --- |
| 价格范围 `[L, H]` | 本侧建仓的价格范围 | 75 到 95 |
| 最大仓位 `M` | 本侧最多持有的数量 | 1 BTC |
| 主仓比例 `r` | 只在单侧网格中可设 | .7 |
| 主仓批数 `n` | 主仓分几批买入；`r = 0` 时不需要 | 4 |
| 网格间距 `d` | 网格格子之间的价格间距 | 1 |
| 网格价差 `g` | 每格卖价 = 格子买价 + g；通常等于 d。表单里默认跟随 d，改过 g 就按 g / d 的比例跟随：g < d 卖得快、每次赚得少，g > d 买得密、拿得久 | 1 |
| 限速（可选） | 任意 τ 时间内最多启动一个单位（第 4.1 节） | τ = 60 分钟 |
| 观点失效价（可选） | 价格越过它时，认为本侧观点不成立；多头侧必须低于 L，空头侧必须高于 H（第 7.5 节） | 70 |
| 失效后剩余数量 `R` | 失效时减仓到的剩余数量，0 表示全部平仓；不超过本侧主仓总量；中性网格固定为 0 | 0 或 .3 |
| 失效平仓滑点上限 | 失效平仓单相对标记价最多让出多少 | 1% |

账户级配置（同一账户所有策略共用）：

| 配置 | 含义 | 默认 |
| --- | --- | --- |
| 保证金率提醒阈值 | 账户保证金率超过它时提醒用户 | 30% |
| 保证金率停止阈值 | 账户保证金率超过它时，停止所有增加敞口的订单 | 50% |
| 行情过期时间 | 读到的行情超过这么久，视为行情过期（第 7.2 节） | 10 秒 |
| 资金费率提醒阈值 | 资金费率对本策略不利、年化超过它时提醒（第 7.6 节） | 年化 50% |

用户只需要表达“主仓分几批买”和“网格多密”。批次与格子怎么对应，由系统按第 3 节自动确定，并在预览中显示。

每个策略还要选标的。杠杆不在策略参数里：用户在交易所上设置，系统读取当前倍数用于资金预检；满仓压力测试按全仓、账户余额和维持保证金档位计算。只支持全仓，标的是逐仓时预览拒绝。一个标的同一时间只能有一个运行中的策略。

### 2.3 配置校验

**规整**：价格按合约报价精度规整，数量按数量精度向下规整（[HL 报价与数量精度](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/tick-and-lot-size)）。以下校验都使用规整后的值，并要求规整后每格卖价高于买价。

**最低金额**：HL 永续最低订单金额为 10 美元（[官方错误说明](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/error-responses)），拒单状态为 `minTradeNtlRejected`。
- 每批主仓买入：数量 × 批次价 ≥ 最低金额。
- 每个格子：按两条腿中较低的价格计算（多头侧是格子买价，空头侧是开空价 − g，即买入平仓价），格子数量 × 该价格 ≥ 最低金额的 3 倍 + 两个数量步长 × 该价格。这样，格子被部分成交拆成持有和已卖出两部分时，至少有一部分可以下单（第 4.4 节）。
- 不满足时，预览提示“网格太密”或“批数太多”，并给出当前资金下可设的最大格数。

**只积累主仓**：`r = 1` 时没有网格，相当于带限速的分批挂单；不需要也不校验网格间距、价差和格子金额，只校验每批主仓买入金额。

**每批都要有格子**：`r < 1` 时，每一批的段内至少要有一个格子；否则这一批的网格部分无处分配，实际主仓比例会偏离配置。不满足时拒绝，提示减小网格间距或减少批数。

**满仓压力测试**：按第 7.3 节计算，满仓时的预计保证金率达到停止阈值就拒绝配置，超过提醒阈值时警告。

**扣费后盈利**：每格的 `(卖价 − 买价)` 必须大于 `(卖价 + 买价) × taker 费率`，即双边都以 taker 成交仍然盈利；否则拒绝配置。预览同时显示按 maker 成交的收益。费率以账户费率（`userFees`）为基础；第三方市场的标的再按部署者的费用设置调整（附录 A），每次预览现取，读不到就拒绝。推荐折扣和对齐稳定币折扣没有算，结果向上取整，都是偏保守的方向。

### 2.4 策略生命周期

1. **新建**：在网页上填写参数，保存为草稿。
2. **预览**：显示校验结果、批次与格子表、启动后会立即成交的订单、每格扣费后收益、满仓压力测试与强平价。标的已有仓位时，同时显示第 8 节的接管分配。
3. **确认启动**：用户确认预览后才开始下单。预览超过 60 秒，或者预览之后仓位、启动后会立即成交的订单有任何变化，或者可用资金减少超过 1% 时，要求重新预览。行情本身每时每刻都在变，不单独作为失效条件；可用资金也一样：有持仓时它随浮动盈亏一直在变，任何变化都作废的话预览永远确认不了，所以只看明显的减少。
4. **运行中**：可以暂停、恢复、停止。暂停和停止先进入“只撤单”状态（暂停中、停止中）：不下新单，后台继续撤单、查询订单终态、补记成交；全部订单结束且成交对完账后，暂停才算完成、停止才归档。进程重启后，原来运行中的策略先进入“恢复中”，遗留订单收干净之后才重新挂单。
   - **停止**：撤销本策略全部订单，策略结束。确认停止之后再问一次是否市价平仓：选了就在撤单收尾后平掉标的上的净仓位（第 7.7 节），没选仓位保留。
   - 运行中**不能修改**价格范围、最大仓位、主仓比例、批数、网格间距和价差。要换这些参数，就先停止，再新建策略接管现有仓位。
   - 运行中**可以随时修改**观点失效价、失效后剩余数量、失效平仓滑点上限和限速间隔。它们不影响已有的批次和格子，修改后立即生效；失效价仍须满足第 2.2 节的约束。
5. **观点失效**：越过失效价后进入“失效中”（第 7.5 节），这时只能停止，不能暂停、恢复或改参数；停止就是放弃剩下的减仓，撤单归档，同样会问是否市价平仓。
6. **市价平仓**：“平仓中”只能停止（放弃剩下的平仓，归档为已停止），不能暂停、恢复或改参数（第 7.7 节）。
7. **结束**：停止、观点失效或市价平仓完成后归档（已停止、已失效、已平仓），只读查看，不能恢复；保留参数版本、订单和成交记录。标的上还有仓位时，归档的策略仍可市价平仓（第 7.7 节）。要继续做，新建策略按第 8 节接管剩余仓位。

## 3. 批次与格子

以多头侧为例。

### 3.1 批次（主仓）

- 把 `[L, H]` 均分为 n 段，段宽 `w = (H − L) / n`。
- 第 k 批（k 从 0 开始）的批次价是 `H − k × w`，对应的段是 `(H − (k+1)w, H − k × w]`。
- 每批数量：把 M 按数量最小单位平均分成 n 份，除不尽的余数依次多给靠近空隙的批次，使各批合计正好等于 M。每批的主仓 `C = ceil(r × q)`，按数量最小单位向上取整；网格部分 `G = q − C`。

### 3.2 格子（网格）

- 格子买价从 H 开始，每隔 d 一格，直到高于 L 的最后一格。每格卖价 = 买价 + g。
- **跟随关系**：每个格子跟随它所在段的那一批，即价格上最先到达它的那一批主仓。
- **数量**：一批的网格部分 G 平均分给跟随它的格子，余下的最小数量单位依次分给靠近批次价的格子。网格间距和段宽不整除时，各批的格子数会不同，每格数量也略有差异；每一批仍严格保持主仓比例。

`r = 0` 时没有批次：每个格子自成一个单位，格子数量 = `M / 格子数`。

**例**：`[75, 95]`，M = 1，r = .7，n = 4，d = 1，g = 1。
- 段宽 5，批次价为 95、90、85、80，每批 .25：主仓 .175，网格 .075。
- 格子为 95、94 … 76，共 20 格。95 到 91 跟随 95 批，90 到 86 跟随 90 批，依此类推。
- 每格 .015。价格以千美元计时，每格按买价约 1,140 到 1,425 美元，满足最低金额。

### 3.3 状态

| 对象 | 保存的量 |
| --- | --- |
| 批次 | 主仓累计成交 `F`（`0 ≤ F ≤ C`）；是否已结束 |
| 格子 | 是否已启用；待买回量 `S`（`0 ≤ S ≤ 格子数量`） |

推算的量：
- 格子持有 = 格子数量 − S；
- 主仓 = Σ F；
- 应有持仓 `h` = 主仓 + Σ 已启用格子的持有量。

## 4. 运行规则

### 4.1 启动单位与顺序

**启动单位**：`r > 0` 时是批次；`r = 0` 时是格子。

**顺序**：每侧从靠近空隙的一端开始。多头侧从最高处往下，空头侧从最低处往上。做多网格相当于从最高批开始，做空网格相当于从最低批开始。

**限速**（可选，每侧独立计算）：
- 同一侧同一时间最多一个单位在等待启动。
- 一个单位第一笔成交之后满 τ，才放行下一个单位。
- 已启动单位的后续成交、格子的买卖循环，都不受限速约束。

### 4.2 批次的主仓买入

1. 批次放行后，在不高于批次价的价格挂主仓买单，数量为 C。当前价已低于批次价时，按批次价下可立即成交的限价单，不付高于批次价的价格。
2. **随成交逐步启用格子**：本批主仓成交 F 时，本批格子从靠近批次价的一端开始启用，启用数量至少为 `floor(本批格子数 × F / C)`；已启用的格子不会关闭。七三比例在主仓部分成交时也保持。
3. **结束**：F 达到 C 时，启用本批全部格子。剩余数量按批次价计算就不足最低下单金额时（例如暂停撤单后只剩一点尾量），本批提前结束：按四舍五入启用 `round(本批格子数 × F / C)` 格（不少于已启用的），其余格子不再启用，界面显示少建的主仓和网格数量。提前结束不阻挡下一批。
   - 剩余数量按批次价足够、只是因为第 6 节的下调使实际可挂金额不足时，不结束本批，主仓买单暂不挂出，等待原因为“限价因自身反向订单下调”。自身卖单成交或价格回到批次价后，照常补齐。
4. 价格还没到批次价时，主仓买单挂在批次价等待，不追高。

### 4.3 格子的网格循环

- **启用**：格子启用时，状态为“全部待买回”（S = 格子数量），在格子买价挂买单。当前价已低于格子买价时，这张单立即成交。这是网格启动的正常行为，不受限速约束。
- **持有部分**（格子数量 − S > 0）：在卖价挂卖单。做多或做空网格的卖单标为只减仓；中性网格不标（第 5.2 节）。成交后 S 增加。
- **待买回部分**（S > 0）：在格子买价挂买单，成交后 S 减少。

格子部分成交时，买单和卖单可能同时在场；卖价高于买价，两张单不会互相成交。

### 4.4 小额剩余

格子的某一侧剩余量不足最低下单金额时（按实际可挂限价计算，含第 6 节的调整）：
1. 这一侧先不挂单，只挂另一侧。
2. 另一侧全部成交后，格子恢复为整份（全部持有或全部待买回），再按整份挂单。

第 2.3 节的配置约束保证两侧不会同时不足。

### 4.5 订单与记账

- 每张订单在发送前确定：属于哪个批次或格子、用途（主仓买入、格子买入、格子卖出）、限价、数量、客户端订单 ID（HL `cloid`）。
- 授权时预留数量：
  - 主仓买入：不超过 `C − F` 减去本批在场主仓单的余量；
  - 格子买入：不超过 `S` 减去本格在场买单的余量；
  - 格子卖出：不超过 `格子数量 − S` 减去本格在场卖单的余量。
- 成交只改它所属批次或格子的计数。数量已预留，所以成交以任何顺序到达都得到相同状态，不需要跨订单的成交排序。

### 4.6 启动时价格已越过部分单位

例如中性网格的空头侧为 91 到 95，启动时价格在 93：91、92、93 三个空头格子按顺序放行后，会以不低于各自格子价的价格立即开空。开启限速时按限速逐个放行。

预览会写明启动后将立即成交的数量和价格，由用户确认；不想立即成交，可以调整价格范围。

## 5. 做空与中性

### 5.1 空头侧

空头侧是多头侧的镜像：

| | 多头侧 | 空头侧 |
| --- | --- | --- |
| 批次价 | 从 H 往下 | 从 L 往上 |
| 主仓 | 买入多单，永不卖出 | 卖出开空，永不买平 |
| 格子循环 | 格子价买入，买入价 + g 卖出 | 格子价卖出开空，开空价 − g 买入平仓 |
| 启动顺序 | 从最高处往下 | 从最低处往上 |
| 单边突破 | 向上突破：格子全部卖出，只留主仓多单 | 向下突破：格子全部平仓，只留主仓空单 |

以上各节中的“买”和“卖”，对空头侧都对调。

### 5.2 中性网格

- 两侧同时运行，都没有主仓；每侧按自己的配置运行。
- 净仓位会在多空之间穿越零，所以格子订单不标只减仓。最大敞口由各侧格子数量控制：多头最多为多头侧 M，空头最多为空头侧 M。
- 偏多或偏空的程度，用两侧的价格范围、空隙位置和各自的 M 表达。例如多头侧 79 到 89、M = 1，空头侧 91 到 96、M = .25，就表达了“下方多做、上方少做空”。

### 5.3 换方向

一个标的同一时间只运行一个策略。改变网格类型或方向时，先停止策略、处理仓位（可以停止时选择市价平仓，第 7.7 节），再按第 8 节接管。系统不自动跨零换方向。

## 6. 自身订单冲突

**何时出现**：本策略的买单价格不低于本策略在场卖单价格时，两张单可能互相成交。正常行情中不会出现：多头侧下跌时高处先买、上涨时低处先卖；空头侧反之；中性网格两侧之间有空隙。但在两种情况下会出现：某个单位的订单因资金不足、结果未知等原因没能按时成交；接管已有仓位后，格子卖单已在场而本批主仓还没买完（第 8 节）。

**规则**：新订单的限价不得与本策略在场的反向订单相交。
- 买单限价最高到“本策略在场卖单最低价 − 一个报价单位”；
- 卖单限价最低到“本策略在场买单最高价 + 一个报价单位”。

调整只会让买单更低、卖单更高，不会劣于原价。订单不用等待，只是暂时只能和外部订单成交。在场订单都按这条规则下出，因此彼此不会相交。

例：接管后价格在 88，90、89、88 三格分别在 91、90、89 挂卖；90 批补主仓的买单从 90 调整为 88.99，仍能买到市场上低于 89 的卖盘。

仍然发生自成交时，HL 会撤销在场的那张单（订单状态 `selfTradeCanceled`），按该单终态处理后重新规划。

## 7. 安全底线与风控

风控按仓位、保证金和价格设计，不设日亏损、总亏损金额限额：这个策略本来就在下跌中分批积累，浮亏增加是预期内的，按亏损金额停止会在最该积累的时候停掉积累。

### 7.1 安全底线

1. **不卖主仓**：普通运行中，策略不会为主仓发出平仓单。格子卖单的数量不超过本格持有量；单侧网格中，卖单还标为只减仓。主仓只在观点失效时按第 7.5 节减仓，或在用户确认市价平仓后按第 7.7 节平掉。
2. **不超过最大仓位**：会增加敞口的订单只有主仓买入和格子的买回或开仓，数量都受本批、本格的预留约束，所以每侧持仓不超过该侧 M。
3. **仓位核对**：交易所实际仓位与应有持仓不一致，且不能用在场订单的成交解释时，暂停整个策略并提醒用户。不自动判断差额属于主仓还是网格。

### 7.2 系统状态闸门

原则：**系统状态不对，本策略就不发任何新订单；撤单始终允许。** 下表各状态的区别只在于已在场的挂单是否撤销。

| 状态 | 已在场的挂单 |
| --- | --- |
| 行情过期（超过行情过期时间没有收到有效报价） | 保留：它们挂在预设价格上，不依赖行情 |
| 成交或订单查询失败（这一步没核对完） | 保留 |
| 本策略有订单结果未知（第 9.2 节） | 保留；整个策略不发新单，有了结论后恢复。规划本来就要撤的单照常撤 |
| 保证金率读不到或数据过期 | 保留 |
| 仓位核对失败，或成交记录和订单累计成交量对不上 | 全部撤销，暂停策略；暂停原因一直显示到用户恢复 |
| 被交易所以操作次数超限拒绝（第 10 节） | 全部撤销，暂停策略；暂停原因一直显示到用户恢复 |

账户模式不是 Unified 时拒绝启动（第 10 节）。

订单结果未知通常在 `expiresAfter` 过期并核对后就有结论（第 9.2 节），停发新单的时间很短。

例外是第 7.5 节的失效平仓和第 7.7 节的市价平仓：它们只发只减仓单，数量按向交易所实时查询的仓位计算，因此在成交查询失败、订单结果未知或保证金率读不到时仍然执行，也不因操作次数超限暂停。行情过期时限价算不出来，也不发单。

### 7.3 满仓压力测试（配置时）

预览时假设本策略所有批次和格子都已成交，价格到达最不利的位置：设置了失效价时取失效价，否则取范围的不利边缘（做多为 L，做空为 H）。中性网格两侧分别计算：多头侧在下方满仓、空头侧在上方满仓，不让两侧数量相互抵消。计算此时的账户保证金率和强平价，账户上已有的其他仓位按当前标记价一并计入，因为 Unified 账户共用余额。
- 预计保证金率达到停止阈值：拒绝配置。否则运行中会在加满之前被第 7.4 节停住，配置表达的仓位实际做不到。
- 超过提醒阈值：警告，并给出满足阈值的最大仓位或杠杆。
- 预览始终显示每一侧满仓时的最不利价格、保证金率和强平价。

这是基于当前账户状态的估算，不是保证。其他仓位和余额变化后，以运行时的第 7.4 节为准。

### 7.4 保证金率限制（运行时）

- **指标**：Hyperliquid Unified 账户比率，按官方账户模式页面给出的计算方式：全仓维持保证金占用（取 `crossMaintenanceMarginUsed` 与「余额 − 维持后可用量」中较大的那个），除以 USDC 余额减去逐仓保证金；分母不是正数时按 100% 算。逐个市场只查本系统用到的：主市场，加上活动策略（预览时加上草稿）的标的所在的第三方市场，各处的全仓占用和逐仓保证金相加，读数时刻取最旧的；其他市场不单独查询。但「余额 − 维持后可用量」是整个账户的数，其他市场的占用会通过它计入：Unified 账户的余额本来就共用，这样不会低估风险。读数过期（超过行情过期时间）按读不到处理。
- 超过**提醒阈值**（默认 30%）：提醒用户。
- 超过**停止阈值**（默认 50%）：同一账户所有策略只发、只保留交易所只减仓单（成交只会减少该标的的净仓位），其余挂单全部撤销。单侧网格的格子卖单本来就是只减仓单，照常运行；中性网格的格子单可能让净仓位穿越零，在此期间撤销。失效平仓照常运行。比率回落到停止阈值以下后自动恢复。

### 7.5 观点失效价（可选，每侧一个）

用价格表达止损：价格越过失效价，说明这一侧的观点不成立。

不设失效价，表示这一侧不启用自动止损，由用户自己管理；系统不提供“越过失效价只停止、不减仓”的选项，因为它和不设失效价没有实质区别。

1. **触发**：标记价越过失效价。多头侧是低于失效价，空头侧是高于失效价。读到标记价那一刻还新鲜（不超过行情过期时间）就判断，越过了立即进入“失效中”，之后别的读取失败或拖到过期都不影响。运行中、恢复中、暂停中、已暂停的策略都会触发：失效价是止损，暂停只是先别做网格，暂停期间仓位还在；停止中不触发，停止就是用户决定自己接管仓位。
2. **撤单**：撤销本策略全部在场订单，等撤单结果并吸收最终成交。
3. **减仓**：把本侧仓位减到剩余数量 R，R 为 0 时就是全部平仓。用立即成交否则撤销（IOC）的只减仓限价单执行，限价相对标记价最多让出设定的滑点上限；让满之后不足最低下单金额时，限价只让到刚好够。没成交完就按新的标记价继续，直到仓位不超过 R。每次补发的减仓数量 = 实时仓位 − R − 本策略所有还可能成交的减仓单余量（含结果未知的），不足最低下单金额就不发。例外是 R = 0（含中性网格）：这一单把整个仓位平掉，交易所对这种只减仓单不设最低金额（附录 A），零头照样发；但还有别的减仓单没有结论时，补发的不是整个仓位，仍按最低金额来。
   - **先减网格、再减主仓**：减仓的成交不改批次和格子的记录（按实时仓位卖，可能卖掉账上还没记入的成交，先记账会把那部分丢掉），应有持仓直接扣掉已卖出的数量；批次表和格子表按已卖出的总量，从离空隙最远的格子、最后一批主仓减起，现算显示。结果与成交到达的先后无关。
4. **结束**：同时满足两项才算失效完成：本策略所有还可能成交的订单（增仓和减仓）都有了结论（已终态，或按第 9.2 节核对为没有影响），且实际仓位不超过 R，或超出 R 的部分按标记价不足最低下单金额（R > 0 时这部分无法下单，界面显示尾量；R = 0 时零头照样平掉，只有小于最小下单数量的才算尾量）。判断用的行情过期时不算完成，下一步重读。完成之前如果有迟到的成交使仓位超过 R，继续按第 3 步减仓。完成后策略进入“已失效”，和已停止一样归档只读，不再自动下任何单；价格回来也不自动恢复，由用户决定是否重新配置，并按第 8 节接管剩余仓位。

失效中只能停止，不能暂停、恢复或改参数（第 2.4 节）。进程重启不打断失效：失效中的策略不进入“恢复中”，重启后接着减仓。

中性网格任一侧失效时，整个策略按全部平仓处理。

### 7.6 资金费

界面显示当前资金费率、累计资金费，以及它占网格已实现利润的比例；资金费率对本策略不利、年化超过提醒阈值时提醒用户。不自动交易，是否调整由用户决定。

- **费率**：Hyperliquid 每小时结算一次，`metaAndAssetCtxs` 的 `funding` 是当前每小时费率，正数多头付空头。年化 = 每小时费率 × 24 × 365，按交易所给的原始精度算。“对本策略不利”按实际净仓位的方向判断（正费率多头付、负费率空头付）；还没有仓位时按单侧网格的方向，中性网格没有仓位时不提醒。暂停的策略同样提醒。
- **读取**：常驻服务单独每 10 分钟读一次活动标的的费率和结算，不在交易的一步里读（这个接口权重高，慢或超时不能拖住撤单和止损）；半小时没读到新的就当读不到。
- **累计资金费**：策略建立之后（归档的到归档时刻为止）这个标的的结算合计；结算每次往前多查 2 小时，按时刻去重。
- **盈亏都按实际成交算**，不用交易所的持仓均价和未实现盈亏——交易所把后来被网格卖掉的买入也摊进均价，网格卖出时均价又不变，和策略手上这些仓位的成本对不上（`strategy/src/pnl.rs`）。
  - **配对**：每批主仓、每个格子各自按时间先进先出，建仓腿的成交进队尾，平仓腿的成交从队头取。接管来的持有量没有成交，按计划建仓价放在队头。成交价和手续费取成交流水（手续费另存一张表 `fill_fees`）；流水缺了（服务停过很久）按限价补，交易所没给手续费的（这张表之前记的成交）按费率估算，挂单腿按 maker、失效减仓和市价平仓按 taker。成交和账本对不上时以账本为准。
  - **网格已实现利润**：格子平仓腿卖出的钱减去配对的建仓成本和两边手续费。
  - **减仓已实现**：失效减仓和市价平仓按账本从每个单位扣掉的数量从队头取，成交金额减去这部分成本和手续费，两侧分开算。市价平仓会连账本外的仓位一起平掉（包括归档之后再平掉的），那部分不是本策略的：按发出的先后，每张单只有不超出账本减掉数量的那部分成交算本策略的，金额按占比折算。没有减仓成交时不显示。
  - **持仓均价**：还拿着的那几份按成交价加权（不含手续费）；中性网格两侧相抵后按净持仓算。没有净持仓、或者算出来不是正数时不显示。
  - **浮动盈亏**：净持仓 × 标记价 − 还拿着的那几份的成交金额和建仓手续费。
  - **合计**：网格已实现利润 + 减仓已实现 + 累计资金费 + 浮动盈亏。
  - **保本价**：标记价到这里时合计为零；算出来不是正数时不显示。

### 7.7 市价平仓

用户确认之后，平掉标的上的全部净仓位。Hyperliquid 没有真正的市价单：官方 SDK 的市价平仓是一张只减仓、立即成交否则撤销（IOC）的限价单，限价按价格让出 5%（附录 A）。这里做法相同，并且一次没平完会接着发。

1. **入口**：
   - **停止时**：第一次确认停止之后，紧接着问“是否市价平仓”，显示交易所上这个标的的净仓位、标记价和最差成交价（标记价让出 5%）。选“市价平仓”，这次停止带上平仓标记；选“保留仓位”或关掉询问，就是普通停止（B45）。净仓位为 0 时不问。
   - **停止中和已归档时**：详情页有“市价平仓”按钮，确认内容同上。停止中点了，等于补上平仓标记；已归档（已停止、已失效、已平仓）点了，策略从归档状态进入“平仓中”。条件：交易所上这个标的的净仓位不为 0（不足最低下单金额的零头也可以平，附录 A），并且这个标的上没有别的未归档策略，否则拒绝并说明原因。
2. **顺序**：带平仓标记的停止，先按停止的规则撤单、等撤单结果、补记成交；全部订单有了结论之后进入“平仓中”。平仓一定排在撤单收尾之后，不会出现刚平掉、残留的网格单又成交把仓位开回来的情况。
3. **平仓**：按交易所实时净仓位的方向下单，多仓卖、空仓买，只减仓、IOC。限价 = 标记价让出 5%（卖出取下方、买入取上方），按报价精度规整时不让得更多（卖出向上取、买入向下取），5% 是上限，和失效减仓同一规则。数量 = 实时净仓位 − 本策略还可能成交的平仓单余量（含结果未知的）。这一单把整个仓位平掉时，不足最低下单金额的零头也照样发（附录 A）；还有平仓单没有结论、这一单只是其中一部分时，不足最低金额就先不发，等那张单有结论。没成交完，下一步按新的标记价接着发。5% 是固定值，不设成参数。
   - **平掉的是整个标的的净仓位**：包括接管来的仓位和用户在交易所上手动开的仓位。一个标的同一时间只有一个未归档策略，不会动到别的策略。弹窗显示的就是要平的实际数量。
   - **记账**：和失效减仓一样，平仓成交不改批次和格子的记录，批次表和格子表按已平掉的数量现算扣减（第 7.5 节第 3 步）。
4. **闸门**：行情过期或读不到仓位时这一步不发单，下一步再试；保证金率超过停止阈值不影响平仓（只减仓单本来就放行）。
   - **结果未知的平仓单**：作废时不看“仓位一致”这一项（第 9.2 节第 3 条的例外）。平仓单只减仓、IOC，过了期限不会再成交；下一张按实时仓位算，这张就算悄悄成交过，实时仓位里也已经扣掉，只减仓限制保证不会平过头。账上的应有持仓在平仓时本来就可能和实际不一致（归档后手动交易、仓位核对失败暂停过、平仓途中手动交易），要求一致的话这张单永远作废不了。仓位读数还在变时不发平仓单，也不算平完；失效减仓同样在读数还在变时不算完成。
5. **结束**：本策略所有还可能成交的订单都有了结论，并且实际净仓位为 0（零头也照样平掉，只有小于最小下单数量的才算尾量，界面显示）。完成后进入“已平仓”，归档只读。
6. **放弃**：平仓中可以停止，停止就是放弃剩下的平仓：撤掉在场的平仓单，收尾后归档为已停止，剩余仓位保留。已经确认平仓、还在停止中收尾时再停一次（例如命令行紧急停止），平仓照样做。
7. **重启**：进程重启不打断平仓；平仓中的策略不进入“恢复中”，重启后接着平。
8. **归档后仍有仓位**：已归档的策略不再走步，读数停在归档那一刻，不能拿来判断现在还有没有仓位。常驻服务每分钟读一次已归档策略所在标的的净仓位，只读、不下单，读到的时刻一起记下。`clearinghouseState` 一次返回一个合约市场上的全部仓位，没有跨市场一次读完的接口（附录 A），所以按市场读：只涉及主市场就是一次请求，用到第三方市场再各加一次，不按标的逐个查。读不到时沿用上一次的读数并标出读数时刻；5 分钟没读到新的就当读不到，不显示“仍有仓位”，也不给平仓按钮。仓位按标的算，不按策略算：同一标的有几份已归档策略时只算一处，挂在最近归档的那一份上。

## 8. 首次接管

**实际仓位为零**：直接启动。

**已有仓位**：
1. 方向必须有对应的一侧；数量不能超过该侧 M；否则拒绝接管。
2. 从靠近空隙的一端开始分配：
   - **有主仓时**：逐批分配。每个完整的批视为主仓买入已结束、全部格子持有。最后一批只分到一部分：主仓记 `min(C, ceil(r × 剩余))`，其余为网格数量；从靠近批次价的格子开始依次填满，最后一格只持有一部分、其余记为待买回。启用的格子就是填入了网格数量的这些格子；之后本批主仓继续成交时，按第 4.2 节的比例启用更多格子，已启用的不会关闭。
   - **没有主仓时**：逐格分配，最后一格只分到一部分时，其余部分记为待买回。
3. 接管不占用限速：下一个单位按正常规则排队。
4. 交易所上已有的、非本系统下的订单不擅自撤销；预览中列出，由用户处理。

**例**：做多网格（第 3.2 节的例子），已有 .37。
- 95 批完整：主仓 .175，95 到 91 五格各持有 .015。
- 90 批分到剩余 .12：主仓 `ceil(.7 × .12) = .084`，网格 .036。90、89 两格各持有 .015；88 格持有 .006，待买回 .009。90 批主仓还差 .091，照常挂在 90 等待。
- 接管后应有持仓 = .175 + .075 + .084 + .036 = .37，正好等于实际仓位。
- 预览列出接管后会立即挂出的卖单和主仓买单，由用户确认。

## 9. 异常与恢复

### 9.1 发送

- 发送前把订单写入数据库；写入失败就不发。
- 每张单带 `expiresAfter`，设为发送时刻加几秒。HL 官方说明：超过该时间戳的动作会被拒绝。来源：[exchange endpoint](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/exchange-endpoint)。

### 9.2 结果未知（超时、断连、含义不明的错误）

1. 按第 7.2 节，本策略暂停发送任何新订单（规划本来就要撤的单照常撤，其余挂单保留），直到这张单有了结论。保留这张单的预留数量，不换 `cloid` 重发。
2. 按 `cloid` 查询订单状态。查到 open、filled、canceled 等状态，就按状态处理，结束未知状态。
3. 查不到（返回 `unknownOid`）时，只有交易所从没确认过它在场（没有拿到过交易所订单编号）才可能作废：确认过在场、后来又查不到的，可能只是查询滞后，它仍然可能成交，要等交易所给出明确的终态。可以作废的，等 `expiresAfter` 过去再加一段安全余量，然后同时满足以下三项，判定这张单没有任何影响，释放预留：
   - 当前挂单中没有它；
   - 从发送时刻到现在的完整成交记录中，没有属于它的成交；
   - 交易所仓位与应有持仓一致（市价平仓单不看这一项，见第 7.7 节）。
4. 不满足时本策略继续不发新订单，界面显示这张单和缺少的事实。

安全余量取 30 秒。

### 9.3 成交与重启

- **记账以订单状态为准**：每张订单的累计成交量取交易所的挂单列表或按 `cloid` 查到的状态（原始数量减剩余数量），在场的单和已撤销的单一样直接记账；同一订单的累计成交量只接受更大的值。撤单之后、交易所给出最终累计量之前，这个单位不下同用途的新单。
- **成交流水是审计记录**：按交易所成交标识 `tid` 去重后存下，用来留底和把限速的第一笔成交时刻改准，不参与记账，晚到或漏掉都不挡记账、暂停和归档。每一步从上次同步点往前 60 秒开始拉，最多往前 1 小时（Hyperliquid 的成交接口按整个账户返回、只留最近一万笔，查得太远就永远查不全）；同步点只在拉取成功后前进。唯一的例外是第 9.2 节结果未知的订单：它的「没有成交」要从发出时刻查起，回看起点钉在它的发出时刻，几十秒内就有结论。
- **重启**：运行中的策略先进入“恢复中”：等遗留订单的 `expiresAfter` 过去，撤销它们，按 `cloid` 查询终态并记账、核对仓位，收干净之后再按保存的状态重新挂单。不重发旧订单。

### 9.4 暂停、恢复与外部交易

- **暂停**：撤销本策略全部在场订单，等撤单结果并吸收最终成交。状态全部保留。
- **恢复**：按状态重新挂单。限速按真实成交时间计算，暂停不会多给额度。
- **外部交易**：用户在交易所手动交易，会使仓位核对失败，策略随即暂停。用户可以恢复原仓位后继续，或按第 8 节重新接管。

## 10. 资金

- 每张会增加敞口的订单下单前做一次保守预检：所需保证金估算为“数量 × 限价 ÷ 杠杆 + 按 taker 费率估算的手续费”，不超过账户可用保证金减去本系统其他在场同类订单的估算。
- 可用保证金在 Unified 账户下从现货账户状态读取：官方说明 Unified 和组合保证金账户的全部余额与占用都显示在现货账户状态中，单个合约 DEX 的账户状态没有意义。用 `tokenToAvailableAfterMaintenance` 里 USDC（token 0）的可用量，不使用可提现金额。
- 同一账户的所有这类订单经同一个入口依次预检，不并发重复使用同一份可用额度。
- 以交易所最终准入为准：保证金不足被拒后，该单按明确拒绝处理，退避重试（1、2、4、8 秒……最多每 60 秒一次），界面显示原因。
- **账户模式**：用户使用 Unified 账户，本期只支持这一种。来源：[账户模式](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/account-abstraction-modes)。
  - **余额与现货共用**：同一种资产的余额同时为现货和所有全仓合约作抵押。用户自己的现货买卖或其他合约会改变策略可用的保证金，所以每一步第一次要发增仓单时重新读取可用额度，同一步后面的单共用这份额度、逐张扣掉预留。余额变化本身不触发仓位核对暂停；仓位核对只看本标的仓位。
  - **操作上限**：交易所有两个互相独立的上限。Unified 账户每天最多 5 万次用户操作；另有按地址的累计上限，允许次数 = 历史累计成交额（每 1 USDC 算 1 次）+ 初始 1 万次，超限后每 10 秒只放行一次，撤单额度更高，可以用 `reserveRequestWeight` 按每次 0.0005 USDC 买额度。网格策略正常每天远达不到这个量（按 BTC 实际价格路径估算，格距 0.05% 时每天约 1300 次、最忙的一小时约 650 次），所以只做简单处理：
    - 本地按 UTC 日计数，每次下单、撤单记一次；界面显示当日已用次数，超过 80% 时提醒用户（例如减少格子或加大间距）。
    - 下单或撤单被交易所以超限拒绝时，暂停策略并提醒用户手动处理，暂停原因一直显示到用户恢复。只认有出处的原话 `Too many cumulative requests`（按地址的累计上限）；每日上限的拒绝原话文档没有给出，认不出时按普通拒绝处理。失效中不暂停，继续止损。
    - 不为这一情形设计自动的只减仓流程。
  - 启动时读取账户模式；不是 Unified 时拒绝启动，并说明原因，不替用户切换模式。

## 11. 界面

- **顶栏**：当前网络和账户地址。正式网用醒目的颜色标出，避免把正式网当成测试网操作。
- **策略列表**：每个策略的标的、类型（做多、做空、中性）、状态（草稿、运行中、恢复中、暂停中、已暂停、停止中、已归档、失效中、已失效、平仓中、已平仓）、净仓位和挂单数，以及一条价格条（各侧建仓范围、观点失效价、最近的标记价）；已归档的默认收起，但标的上仍有仓位、且这个标的没有未归档策略的，单独列在“仍有仓位”一栏、不收起：显示标的、归档状态、净仓位（按方向着色）和读数时刻，带“市价平仓”按钮（确认弹窗同第 7.7 节）；入口有“新建策略”和“账户风控设置”。
- **页面地址**：每一屏有自己的地址（列表、新建、草稿、详情、设置），刷新和前进后退都回到原处；新建的草稿保存后地址换成这份草稿。
- **新建与预览**：参数表单，以及第 2.4 节的预览内容；确认启动按钮。主仓批数下面显示批次价格从哪排到哪和段宽（例如“主仓 84000 → 76800，段宽 1800”），规划时能看出最远一批落在 L 上方一段；准数以预览里的批次表为准。
- **参数版本**：每次保存的参数和时间。

- **主仓批次表**：批次价、主仓数量、已买入数量、状态（未放行、已放行、已结束），提前结束的批次显示少建的主仓和网格。
- **网格格子表**：建仓价、平仓价、数量、持有、在场订单。按建仓价从高到低排，在标记价的位置插一行标出当前价格。格子用简写，例如“多3”“空0”，属于某一批的标上批号。状态只在格子还没启用时显示（等所属批次）；等买入、持有、部分持有由持有量看出。
- **在场挂单**：归属（多3、多批0、多侧）、用途（开、平、主仓、失效减仓、清仓）、买卖、限价、数量（有成交时写成已成交 / 总量）。按限价从高到低排。状态只在不是“在场”时显示。
- **文案**：面向有经验的用户。正常状态不额外说明，只显示异常和提醒；没有在等的事、也没有提醒时，不显示等待区。服务端给出的说明、提醒和参数校验原因用中文短句：先说哪一侧（做多侧、做空侧），参数用表单上的符号（L、H、M、r、n、d、g、R），能改的说出怎么改。
- **等待原因只有这几种**：价格未到、等待限速放行、等待所属批次、限价因自身反向订单下调、资金不足或退避中、保证金率超过停止阈值、保证金率读不到、行情过期、订单结果待查、成交待对账、仓位数据还在变化、成交记录对不上、仓位核对失败已暂停、观点已失效。
- **详情的读数**：标记价、可用 USDC、账户保证金率、交易所仓位与应有持仓、读数时刻；资金费率（每小时与年化、读到的时刻）、累计资金费、网格已实现利润与资金费占比；持仓均价、保本价、浮动盈亏、合计，有减仓成交时另列减仓已实现（第 7.6 节）；今日操作次数。满仓强平价在预览的压力测试里显示；各侧失效价在参数里显示。
- **说明**：策略为什么还没走完当前状态，以及保证金率、资金费率、操作次数的提醒。
- **运行中可改的参数**：限速间隔和观点失效设置。
- **停止与市价平仓**：停止要确认；确认之后再问是否市价平仓，显示净仓位、标记价和最差成交价，默认按钮是“保留仓位”。停止中和已归档的详情页在满足第 7.7 节条件时显示“市价平仓”按钮。平仓中显示还要平多少。

## 12. 架构与实现方式

**模块**：

| 模块 | 职责 |
| --- | --- |
| `strategy` | 策略计算，纯函数，不含任何 I/O：配置模型与校验、批次与格子划分、规划（要下的单、要撤的单、等待原因）、成交记账、系统状态闸门判断、压力测试计算 |
| `runtime` | 账户执行，唯一写入入口：先写数据库再发送订单、资金预检、成交记账、仓位核对、重启恢复；启动文件与私钥校验；网页使用的 HTTP 接口；常驻服务。交易所和账户接口在这里定义成 trait，测试使用模拟实现 |
| `hyperliquid` | Hyperliquid 适配：签名、元数据与精度、标记价、下单撤单、按 cloid 查询、按时间拉成交（轮询，没有用推送）、Unified 余额与账户比率、费率、资金费 |
| `cli` | 命令行 `poise`：启动校验、常驻服务、状态、紧急暂停 |
| `console` | 网页控制台 |

**重启**：见第 9.3 节。

**需要持久化**：
- 策略参数及版本、账户级风控设置、策略状态（草稿、运行中等）；
- 各批次的 F 与结束标记、各格子的启用标记与 S、限速的放行进度和最近放行时间（接管时直接按第 8 节写成这些状态，不另存基线）；
- 全部订单（含 `cloid`、所属单位和用途）、成交；当前的暂停原因（恢复时清掉，不保留历史）；每日操作次数、资金费结算；数据库所属的网络和账户。

其余数量都可推算。

**范围**：只接 Hyperliquid；其他交易所以后再按同一个交易所接口接入。
