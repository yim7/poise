# 分批主仓与网格：实现计划

本文是临时实现计划，不是长期设计依据。设计依据是 [分批主仓与网格设计](../../docs/layered-grid-design.md)，术语见 [GLOSSARY.md](../../GLOSSARY.md)。全部任务完成后删除本目录。

开发分支：`design/layered-grid`。

## 实现方案（已与用户确认）

1. **从新设计出发重新实现。** 在新目录 `next/` 下建立独立的 Rust 工作区和前端工程，不在旧代码上修改，不兼容旧配置、旧数据库或旧接口。旧代码里能直接用的部分复制过来再裁剪：Hyperliquid 签名、REST/WS 客户端、精度规则、cloid 生成、前端工程脚手架等。
2. **模块**：

   | 模块 | 职责 |
   | --- | --- |
   | `strategy` | 纯计算，无 I/O：配置模型与校验、批次与格子划分、规划、成交记账、闸门判断、压力测试 |
   | `runtime` | 唯一写入入口：先写数据库再发单、资金预检、成交记账、仓位核对、重启恢复、启动文件与私钥校验、HTTP/WS 接口；交易所接口定义成一个小 trait，测试用模拟交易所 |
   | `hyperliquid` | Hyperliquid 适配 |
   | `web` | 网页控制台 |

3. **配置**：策略和账户级风控存在数据库，通过网页管理，每次保存记录一个版本。启动文件只放网络、账户地址、私钥、数据目录和监听地址，放在仓库之外的实例目录，权限 600，由用户自己编写。
4. **重启**：等 `expiresAfter` 过期后撤销本策略遗留挂单，按时间补拉成交并按 cloid 记账，核对仓位，再按保存的状态重新挂单。
5. **范围**：只接 Hyperliquid、Unified 账户；其他交易所以后按同一交易所接口接入。
6. **切换**：新系统全部完成后，删除旧代码，把 `next/` 移到仓库根目录，重写 README 和系统文档（任务 13）。

## 执行要求

- 执行本计划前需要用户确认。每个任务先补验收测试，再实现；本地测试通过才算完成。
- 默认先跑与改动直接相关的最小测试。
- 每个任务验收通过后立即提交，并把提交号写回对应任务文件；完成该记录后再开始下一个任务。无法提交时停止并报告原因。
- 任务文件和测试样例里**不得出现私钥、账户地址、订单号、资金金额等真实账户信息**。录制的交易所响应必须先替换这些字段。
- 测试网：用户已授权，可以直接连接、读取账户数据和下单测试，不需要逐次确认（2026-10-15）。正式网：连接账户或下单都需要用户另行授权。只读或模拟成功不能标记为测试网或正式网通过。
- 设计文档没有规定、属于普通技术细节的，执行者自己决定；影响交易行为的，先问用户。
