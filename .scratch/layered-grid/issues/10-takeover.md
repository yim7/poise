# 10：接管已有仓位

**要构建什么：** 启动策略时如果标的已有仓位，按设计第 8 节从靠近空隙的一端分配给批次和格子，预览中展示分配结果和将挂出的订单。

**被阻塞于：** 05、07

**状态：** done

- [x] 已有 .37 多单接管做多网格，分配结果与设计例子一致、应有持仓等于实际仓位、不占用限速（B21）
- [x] 已有仓位方向没有对应的一侧、或数量超过该侧上限时拒绝（B22）
- [x] 接管后补主仓的买单按自身卖单下调限价（B13b）
- [x] 交易所上非本系统的挂单只列出、不撤销

**说明**：
- 接管是纯计算 `Strategy::takeover_state`：按仓位方向选侧，从靠近空隙的一端分配，分完按主仓成交推进一次批次（与运行第一步一致），限速放行到“已结束的单位数 + 1”。
- 预览与确认启动都从接管后的状态出发；预览新增“第一步挂出的订单”和“交易所上已有的其他挂单”；立即成交按第一步实际规划的限价判断。
- 规划顺序改为先格子后主仓：同一步里格子平仓单保持原价，主仓建仓单避让（第 6 节例子）。
- 挂单列表包含没有 cloid 的手动挂单（`ExchangeOrder.client_order_id` 可空，新增买卖方向），对账只按 cloid 匹配。
- 可用抵押不再进预览指纹：确认时只有低于预览时的 99% 才要求重新预览。原因：有仓位时统一账户的可用抵押随浮动盈亏不断变化，测试网实测接管时永远确认不了。比设计 B43 原文宽松，待用户确认后修订设计。
- 测试网验证：一格策略买入 0.0005 后停止，新策略接管这 0.0005，平仓单立即成交、仓位归零，停止后撤掉买回单；全程无暂停，结束时无挂单、无仓位。
