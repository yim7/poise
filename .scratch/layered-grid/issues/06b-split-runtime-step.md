# 06b：拆分执行步骤（重构）

**要构建什么：** 行为不变的重构。把 runtime 中“执行一步”的大函数拆成三段，并把判定规则移进纯计算：

1. **读取**：向交易所取成交、订单状态、仓位、标记价，组成一份快照。
2. **判定**：纯函数，输入快照与本地状态，输出“暂停 / 等待（原因） / 可以下单”，以及哪些单位的哪些用途不能下单。包括：订单是否对完账、未对完账的单位、仓位核对结论（稳定一致 / 数据仍在变化 / 稳定不一致）、成交记录异常。放在 strategy（或其中一个纯计算模块），可以直接用数据测试。
3. **执行**：只负责撤单、先写库再下单、记账。

同时把 `config.rs` 中生成批次与格子的代码移到 `batch.rs`、`grid.rs`，config 只保留配置模型与校验；精简过长的叙述性注释（保留“为什么”的要点，详细理由引用设计文档章节号）。

并入处理任务 06 评审记录的四处：限速首笔成交时间改用实际成交时间（无时间戳时用接收时间作保守上界，流水到达后校正）；修改限速间隔与执行步骤互斥；发送前检查 `expiresAfter` 剩余有效期，不足时刷新并持久化后再发送；运行中从不限速改为限速改为允许，从修改时刻开始计时。
